## 1. 起因：使用者關機前一句話問出一個真正的 bug

使用者問「模擬單依據策略買的到原則嗎」。查證發現：`screener/swing_stops.py`
的進場價一直是**候選當天（訊號當天）的收盤價**——這個價格在現實中買不到，
因為收盤後才算得出這檔今天達標，不可能回頭用當天收盤價下單。

比對 `research/backtest_longswing.py`，實際採用、驗證過的格是
`entry_mode="next_open"`：訊號日之後**下一個交易日的開盤價**才進場，這才是
真的買得到的口徑。`swing_stops.py` 原本的 docstring 寫「跟回測用的定義一致」
是錯的——沒有真的去比對程式碼，是這輪之前的疏忽。

跟 tw-swing 已經踩過的坑同一個性質（`docs/paper/README.md`／
`scripts/paper_update.py`：「訊號日收盤無條件成交」是假說不是成交，後來
改成 `limit_at_close` 為主口徑）。

## 2. 修法：`swing_stops.py` 加兩階段狀態機

新增狀態 `pending_entry`：訊號當天只記「訊號日 + §5.3 停損參考位
（`risk_stop_ref`）」，**不算進場**。次一個交易日 `update_stops()` 執行時，
用那天的開盤價把 `pending_entry` 轉正成 `candidate`（`entry_date`＝次日、
`entry_price`＝次日開盤價、`first_seen`＝訊號日），移動停損從這時候才開始
逐日追蹤。

**跟回測完全對齊的兩個細節**：
1. 若次日開盤已經跌破訊號日算的停損位（`open <= risk_stop_ref`）——這筆
   訊號放棄，不留任何紀錄（跟回測 `abandoned_below_stop` 一致，訊號報告裡
   本來就有「另有 N 筆訊號在成交當下已跌破停損位而放棄」那句話，現在
   `swing_stops.py` 才真正照做）。
2. 訊號成立後，**進場與否只看次日開盤價格本身**，不因為候選池隔天條件不再
   成立就取消——跟回測的 `next_open` 無條件進場一致。

**沒有改變的部分**：一旦進場（`candidate`），移動停損的更新邏輯（`run_high`
只漲不跌、`trail_stop = max(既有, run_high - 2×atr0)`、跌破當天凍結成
`stopped_out`）完全沒動，這部分本來就沒有進場口徑的問題。
