## 3. 查明結果：「市況 py」到底有沒有差異

tw-hold 有兩個跟「市況／大盤方向」相關的模組，**它們本來就是刻意設計成
兩個不同的東西**（各自的檔頭都寫了為什麼要分開），這輪逐一核對過：

| | `reference/regime.py` | `reference/market_status.py` |
| :-- | :-- | :-- |
| 用途 | **回測分層**的既有量測基準 | 「總經導航」頁的**顯示**用多空卡 |
| 分類 | 三態：多頭／震盪／空頭 | 兩條均線各自獨立判斷（MA60、MA200） |
| 判準 | MA200 + 60日報酬 + 回撤（見下） | 單一均線的乖離帶（±2%） |
| Point-in-time 安全 | 是 | 是 |
| 這次回測用哪個 | **這個**（`regime_at()`） | 沒用到 |

**判準細節**（`reference/regime.py`，跟 `reference/market_status.py` 完全
不共用門檻，不要搞混）：
- 多頭：站上 MA200 **且** 近 60 日報酬 > +5%
- 空頭：跌破 MA200 **且**（近 60 日報酬 < −5% **或** 距波段高點回撤 < −10%）
- 其餘：震盪
- 暖機期（前 200 個交易日算不出 MA200）回 `NA`，不猜成「震盪」

**跟 tw-swing 原始版本比對**（`reference/regime.py` 檔頭自己就寫了
「複製自 tw-swing @c310b60，2026-09-07；上游改動不自動同步」，這句話
隱含的風險是「tw-swing 那邊可能改過、tw-hold 這份沒跟上」）：

```
diff /d/g/claude/tw-swing/src/twswing/data/regime.py /d/g/claude/tw-hold/reference/regime.py
```

**結果：兩份程式碼逐行相同**（只差 tw-hold 版多三行檔頭註解），`git log`
查 tw-swing 那邊 `regime.py` 的歷史也只有一個 commit（`f0a708e`，就是
最初寫出這支模組那次）——**目前沒有漂移，數值上沒有差異**。

🆕 **但抓到一個沒被注意過的不一致**：`research/candidate_pool_survey.py`
（實驗D，可行性普查腳本）在檔案開頭直接 `from twswing.data import regime
as rg`——**繞過 `reference/regime.py`，直接吃 tw-swing 私有 repo 的路徑**
（`sys.path.insert(0, "d:\g\claude\tw-swing\src")`）。而 `research/
backtest_longswing.py`（這次在跑的實驗E）用的是 `from reference.regime
import regime_at`——**吃 tw-hold 自己那份複製過來的版本**。兩份現在邏輯
一樣所以數字不會錯，但**如果 tw-swing 之後真的改了 `regime.py`、tw-hold
這份沒跟著同步，兩支研究腳本會從此算出不同答案卻沒有任何錯誤訊息**——
這是使用者「我記得好像有差異」這個直覺抓到的真正風險所在，只是現在還沒

**建議（下一輪動工前先做，很快）**：把 `candidate_pool_survey.py` 的

自己的複製版本，兩支腳本以後才不會各自算出不同的市況分類。**這不影響

可能疊加，這是下一輪要跑出來的東西，不要用猜的。

   變體，不是原話明確要求的東西）
