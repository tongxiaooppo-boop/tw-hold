## 0. 一分鐘現況

這一輪從使用者問「個股查詢可以切換時間長度，那些表會跟著改變，哪些是
固定？」開始，一路做到「個股查詢」跟「多軌體檢」兩個分頁的圖表顯示邏輯，
中間**我自己犯過兩次方向錯誤、被使用者當場糾正**（見 §3），這份簽呈想請
你順便檢查我這兩次糾正後的結果對不對、還有沒有同類型的錯我自己沒發現。

**這次的處理原則（使用者剛提出，請一併確認我有沒有做到）**：你的審核
意見裡，**屬於 bug 的我會直接修**；**不是 bug、只是改善建議的，我會先
拿去問使用者，不會自己決定套用**——如果你的回覆裡有「這樣做更好」但
不是「這樣是錯的」的意見，請明確標成「建議」而不是「問題」，方便我
照這個原則分流處理。

## 1. 這輪做了什麼（照時間序）

### 1.1 個股查詢頁（`_stock_page()`，`app/streamlit_app.py`）

1. **釐清哪些圖跟著「顯示區間」選擇器變、哪些固定**——K線/PE河流圖/殖利率
   走勢/月營收/法人買賣超跟著變；季EPS/三率/ROE/負債比/現金流/股利圖固定。
2. **重新排序**：跟著變的排在前面，固定的排後面、加分隔線+說明文字。
3. **固定範圍的圖統一視窗長度為 5 年**（`stockcharts.py` 新增
   `QUARTERS_LOOKBACK=20`、`DIVIDEND_YEARS_LOOKBACK=5`，取代原本不一致的
   20季/24季/13年）——**依據**：查過 `screener/screen.py`／
   `factors/factors.py`，價值/定存篩選邏輯本身最長只用到 5 年
   （`div_cut_5y`／`avg_yield_5y`／毛利率5年下滑），沒理由圖表拉得比策略
   本身還遠。每張固定圖的標題都加上實際年數（例如「季 EPS（近5年）」），
   不用讓人猜。
4. **修一個真的存在的 bug**：K線/月營收/法人買賣超/PE河流圖/殖利率走勢
   這 5 張跟著「顯示區間」變動的圖，選了「1年」之類的區間後，程式直接把
   X 軸範圍設成 `[選的區間, 資料最新日]`，**沒檢查這檔股票的資料是不是
   真的有那麼長**——新股（實測 `6921`，2025-12-24 才有第一筆價格資料）
   選預設「1年」會被逼著把 X 軸拉到選取起點早於資料起點，左側留一大塊
   空白。修法：`eff_start = max(選的start, 資料實際最早那天)`，5 張圖都
   加了同樣的 clamp。

### 1.2 多軌體檢頁（`_checklist_page()`，同檔案）

5. **第一次改錯**：把短線軌（`short_checks`）K線/法人買賣超的顯示窗口，
   從原本的「近3個月」硬改成「近12週」，理由是「短線軌裡『籌碼密集區』
   `_ccp()` 計算用 `lookback=60` 個交易日≈12週」。波段軌
   （`swing_checks`）的法人買賣超窗口也從「近4個月」改成「近12週」，理由
   是對齊「法人20交易日淨買超」判準。
6. **使用者指出這個對齊邏輯是錯的**：K線/法人買賣超是連續時間序列圖，
   均線/累計線都是吃**全部歷史**算，顯示窗口只是縮放/易讀性選擇——而且
   CCP 根本**沒有畫在圖上**（只在檢核表文字裡出現一行），完全沒理由為了
   它把顯示窗口拉長。已經**改回原本的 3 個月／4 個月**。
7. **额外加碼**：短線軌的圖表窗口加了使用者可選的「圖表顯示區間」
   （2週/1月/3月，預設3月，`segmented_control`），跟個股查詢頁那個
   「顯示區間」選擇器是同一套精神，套用同一個 clamp 修正（第 4 點）。
8. **價值/定存軌**（`value_checks`／`deposit_checks`）的圖表窗口，比照
   §1.1 第 3 點統一改成 5 年（`ch.roe_trend`／`ch.balance_health` 拿掉
   寫死的 `24`，改吃 `stockcharts.py` 的新預設值 20）。

## 3. 想被挑戰的點

1. **個股查詢頁的「固定 5 年」是不是也犯了同一種錯？** 我的判斷是
   「季EPS/三率/ROE/負債比/現金流/股利圖」都是一根柱子=一期資料，屬於
   §2 第一類（該對齊策略回溯期），跟 K線/法人買賣超那種連續序列不是同
   一類。**這個分類本身對不對？** 尤其 `roe_trend`／`balance_health` 背後
   的 `roe`／`debt_ratio` 是不是真的「一期一個值、不需要額外歷史才能算」，
   還是其實也有隱藏的滾動窗口（比如 TTM 計算需要吃前面幾季）我沒注意到？
2. **`QUARTERS_LOOKBACK=20`（5年）這個數字本身**：我推導的依據是
   `screener/screen.py`／`factors/factors.py` 裡「最長只用到 5 年」
   （`div_cut_5y`／`avg_yield_5y`），但這是**篩選邏輯**用的回溯期，不是
   「使用者想看多久歷史來判斷這檔股票體質」的天然需求——這兩者是不是
   應該分開看？有沒有可能使用者實際上想看比篩選邏輯更長的歷史（比如
   看一次完整的景氣循環），5年反而太短？
3. **§1.2 第 8 點**：`ch.roe_trend`／`ch.balance_health` 拿掉寫死的 `24`
   之後，多軌體檢頁的價值/定存軌圖表現在間接依賴 `stockcharts.py` 的
   模組層級常數 `QUARTERS_LOOKBACK`——這個隱性耦合（改
   `stockcharts.py` 的常數會同時影響兩個分頁）是合理的設計，還是應該讓
   呼叫端明確傳參數比較不會互相牽連？
4. **完全沒有新增/修改測試**——`tests/test_charts.py` 沒有測試涵蓋這次
   的 clamp 修正（新股左側空白）、視窗長度統一、或多軌體檢頁的新選擇器。
   這個缺口有多嚴重？哪些地方最值得補一個回歸測試防止以後改壞？
5. **個股查詢頁重新排序後的 `xstart` 計算**（`app/streamlit_app.py` 約
   1730-1775 行）：`xstart = start if (not d["px"].empty and start is not
   None) else None` 這行利用 Python `and` 短路求值避免 `d["px"].empty`
   時 `start` 未定義的 `NameError`——這個寫法能動，但**讀起來隱晦**，
   算不算技術債？有沒有更清楚的寫法？
6. **多軌體檢頁短線軌新加的「圖表顯示區間」選擇器**（`_checklist_short_range`
   key）：跟個股查詢頁的「顯示區間」選擇器（`_px_range` key）是不同的
   `session_state` key、各自獨立——這是對的（兩個分頁各自查詢邏輯不同的
   股票代號機制，見 `_stock_input()` docstring 的鏡像 key 設計），但**波段/
   價值/定存三軌目前都還是純固定視窗、沒有選擇器**，只有短線軌加了——
   這個不一致（只加一軌）合不合理？還是應該四軌都比照辦理（但這是「建議」
   不是「bug」，照這次的分流原則只需要標出來，不用直接做）。
