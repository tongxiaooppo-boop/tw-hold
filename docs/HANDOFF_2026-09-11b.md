## 1. 這一輪做了什麼（2026-09-11）

使用者主動提「今天不改程式，最多修朋友回報的 bug」，但接著又要求先做視覺改版——
確認過（AskUserQuestion）後直接套用，不是踩紅線。四顆 commit：

### ✅ 配色改版「北歐靜謐」方案 C（`d928916`）

使用者貼一份給通用持股追蹤 app 的配色規格（淺色、Manrope + JetBrains Mono、
統計卡依用途暈染）。**這份規格是套「總市值/今日損益/總報酬率」的個人部位追蹤
模板，tw-hold 實際上沒有這種 UI**——所以做的是把色票/字體系統原樣套用，卡片
暈染色改對應既有的 good/warn/neutral **判斷類別**語意（不是市值/損益/報酬率）。

- `app/streamlit_app.py` `_CSS`：`:root` 全面換色票（背景 #EEF1F4、卡片白底
  #FFFFFF、good=#5C7A72/bg #DEE9E6、warn=#8A6A5F/bg #F1E3DF、neutral=#5E7686/bg
  #DEE7EC）、字體 Manrope（一般文字）+ JetBrains Mono（取代 IBM Plex Mono，
  所有數字）、中文股名維持 Noto Serif TC（Manrope 無 CJK）、表格分隔線 0.5px。
  **色源只有這個 `:root` 區塊**，其餘規則一律吃 `var()`，之後要微調直接改這裡。
- `app/stockcharts.py`：8 張 plotly 圖 `plotly_dark` → `plotly_white`；K 線紅漲
  綠跌改 #C4574A/#4A7D74（**這是唯一的漲跌色**，跟卡片判斷色分開，不要混用）；
  其餘輔助線（YoY、負債比、流動比、殖利率、PE 河流圖）色改套新色票。
- `.streamlit/config.toml`：`base` 深色 → 淺色，跟新 CSS 對齊，避免原生元件
  （按鈕/expander）用舊深色地基打架。

### ✅ App 表頭改名：持股觀測站 → 股市雷達（`3200a2b`）

配色改版順便重定表頭。過程經過三輪 AskUserQuestion 收斂——中途「選股雷達」
「智慧股市雷達」都因為字眼暗示主動選股/AI 判斷（跟非投顧、純規則、無 runtime
LLM 的定位衝突）被使用者自己否決，定案 **「股市雷達」**。`docs/ME_CHECKLIST_
MAPPING.md`「App 表頭改名」節補記了整段決策過程（含被否決的候選跟理由）。
repo 名字仍是 `tw-hold`，只改網頁 `st.title`/`page_title`。

### ✅ 表頭加 📡 icon（`58947e9`）

使用者問「雷達出現在名字裡，程式沒半個雷達」。討論後決定**只做識別層級**：
favicon（`page_icon="📡"`）+ 標題文字前綴，不做雷達圖表（討論過個股查詢頁加
多軸雷達圖的方案，但会被誤讀成綜合評分、碰到「多軌體檢不加總不評分」的紅線，
使用者選了保守版）。

### ✅ 主動式 ETF 頁新增「五檔加總」總表（`e94c2fa`）

使用者問「新增哪些、減少哪些」的統計難不難做。討論後選**推薦方案**：純 app
端彙總，不動 `build_active_etf_flags.py` 管線（複用既有 `flags` 的 `kind`/
`buyers`/`sellers`/`net_shares`）。新函式 `_active_summary(fl)`，插在五張基金
卡片上方一張彙總卡「整體加碼」vs「整體調節」。

**分歧怎麼處理（使用者主動問的關鍵設計點）**：方向沿用既有 `kind` 判斷（consensus
優先，否則看淨股數方向——**不是多數決**）；同一檔有買有賣時**不隱藏**，項目旁
直接標「N買M賣，淨額計」。本機用 2026-09-10 真實 PCF 快照跑過：台積電（2 家買、
1 家賣、淨股數偏賣）正確落在「整體調節」且標出「2買1賣」。
