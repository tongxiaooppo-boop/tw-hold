01 開始之前

這是單人使用的決策支援工具，不是多租戶產品——「開始之前」要準備的是帳號與金鑰，不是找使用者名單。

誠實狀態 PRD 目前版本標記為 3.1-draft（未定案）：長波段候選池「只測過每週能篩出幾檔， 沒測過報酬或回撤」；價值／定存線曾在 2026-09-07 做過一次組合回溯（實驗 B）， 但該回溯腳本引用的 twswing.value 之後被搬進 tw-hold、tw-swing 端已刪除， 現在重新執行會直接 import 失敗，數字目前無法重現。三清單已經在跑、App 已經上線， 但背後的因子設計仍視為「假設」而非定案——部署這個系統前請先知道這件事。
要準備的東西用途從哪拿
GitHub 帳號 + tw-swing repo 存取權 tw-hold 的核心資料（財報/日線/估值 bundle）發佈在 tw-swing 私有 repo 的 Release（tag data-latest），tw-hold 完全不 import tw-swing 程式碼，純用 PAT 拉檔案 tw-swing repo 擁有者本人核發
Fine-grained PAT（TWSWING_BUNDLE_PAT） 對 tongxiaooppo-boop/tw-swing 的 contents: read 權限，本地／Actions／Streamlit Cloud 三處都要各自設定 GitHub → Settings → Developer settings → Fine-grained tokens
（選填）FinMind token 只有「個股即時補抓」（查不到 bundle 裡前 500 大以外的個股時）與 resolve_splits.py 自動解析分割才需要，純本地／CI 用，不會落地成公開資料 FinMind 官網申請
（選填）Alert webhook（Discord／Slack） rebuild 失敗、清單超過 180 小時沒重算時告警用，不設也能跑，只是沒人會被通知 自建 Discord/Slack Incoming Webhook
預估時間 本機環境（pip install + 拉 bundle + 跑起來）約 10–15 分鐘； Streamlit Cloud 部署（含填 Secrets）約 10 分鐘；GitHub Actions 排程設定約 10 分鐘。 整套跑通抓 30–40 分鐘，前提是 PAT 已經核發好。

02 部署步驟

分三段：A 本機跑起來（開發／驗證用）、B Streamlit Cloud 上線、C GitHub Actions 每日重算管線。B、C 互相獨立，可以先做 A+B 讓網頁能看，C 之後再接。

A本機環境

  1. 安裝依賴： 
    pip install -r requirements.txt
    requirements.txt 版本刻意釘死（pandas==3.0.3 / pyarrow==24.0.0 / streamlit==1.60.0 / plotly==6.9.0）——不要自己改成 >=，檔頭註解記著這曾經讓 Cloud 抓到跟本地不同版本、個股頁的 K 線圖直接 AttributeError。改版本前務必先本機 pytest -q + streamlit run 都過。
  2. 建立 .env（專案根目錄，已 gitignore）： 
    TWSWING_BUNDLE_PAT=你的 fine-grained PAT
# 選填，只有本地進階模式（查不到的個股即時補抓）才需要：
# FINMIND_TOKEN=你的 FinMind token
  3. 拉上游資料 bundle（第一次跑或想手動更新資料時執行）： 
    python fetch_bundle.py
    會把 tw-swing Release 的財報/日線/估值資料解到 data/upstream/（不進版控，隨時可重拉）。這一步做 schema 校驗（G1，版本不合直接失敗）跟日期新鮮度檢查（G3，不合只標記不失敗）。
  4. 算因子、產出三清單： 
    python build_lists.py
    這一步要用到上一步 data/upstream/ 的資料。輸出 data/derived/{value,deposit,swing}_list.json + _meta.json（進版控）與 factors_*.parquet（不進版控）。
  5. 啟動網頁： 
    streamlit run app/streamlit_app.py
    第一次載入個股查詢頁時，App 自己也會再拉一次 bundle／因子表（@st.cache_resource），所以就算跳過步驟 3–4 也能開起來，只是清單頁會顯示「資料過期」或空清單。
  6. 跑測試確認沒壞： 
    pytest -q
    最近一次交接記錄的基準是 110 passed，可以拿來對照有沒有測試漏跑或新壞掉。
跟 README 對一下 README 目前的「跑」段落只列了 pip install → python build_factors.py → streamlit run → pytest -q， 省略了 fetch_bundle.py 這一步、也沒提到 build_lists.py。 實際 CI（rebuild.yml）用的是 fetch_bundle.py → build_lists.py（它內部呼叫 build_factors.py 的 screen_all()，會產出三清單而不只是 README 註解說的「因子 + 兩清單」）。 這份說明書照 CI 實際流程走；建議之後回頭把 README 的「跑」段落也同步更新。

BStreamlit Community Cloud 上線

  1. repo push 到 GitHub（tw-hold 目前是 public repo；bundle 走 PAT 保護，App 本身公開沒關係）。
  2. 到 share.streamlit.io 建立 App，指到主檔 app/streamlit_app.py，分支選 main。
  3. App → Settings → Secrets，貼上（TOML 格式）： 
    TWSWING_BUNDLE_PAT = "你的 fine-grained PAT"
# 選填：
# FINMIND_TOKEN = "你的 FinMind token"
    這一步要用到「開始之前」拿到的 PAT——沒設的話個股頁會直接顯示「拉不到 bundle」錯誤訊息。
  4. 主題不用另外設定：.streamlit/config.toml 已經把主題釘死成固定淺色「北歐靜謐」（base = "light"）， Cloud 會直接套用，不會跟著使用者系統深色模式切換（這是 2026-09-11 使用者裁決，取代了 2026-09-08 的深色版）。
  5. 之後每次 push 到 main，Cloud 會自動重新部署，不用手動觸發。
目前已上線 tw-hold-jchm8ooiwp7ewqisfzmpoo.streamlit.app （出自最新交接文件，若你是重新部署到自己帳號，網址會不同）。

CGitHub Actions 每日重算管線

  1. repo → Settings → Secrets and variables → Actions，設定：
    Secret必要性用途
    TWSWING_BUNDLE_PAT必要fetch_bundle.py 拉上游資料
    FINMIND_TOKEN選填resolve_splits.py 自動解析未還原分割（continue-on-error，缺了不會擋清單重算）
    ALERT_WEBHOOK選填rebuild 失敗 / 清單過舊 / 分割解不掉時發告警
  2. rebuild.yml（每日重算三清單）依序執行：拉 bundle → 自動解析分割 → 算因子產三清單 + 族群動向排行 → 主動式 ETF PCF 快照與認養旗標 → 因子表上傳到 derived-latest Release → commit 回 data/derived/。 目前刻意只手動觸發（workflow_dispatch）或等 tw-swing 端接上 repository_dispatch（type bundle-published）——PLAN 裡寫「先手動跑幾天觀察再開排程」， 目前還沒有 cron，需要你自己決定要接哪一種自動觸發（檔案內註解列了兩個方案：tw-swing 端 dispatch，或直接在這裡加 cron）。
  3. heartbeat.yml 每週一 UTC 01:00 自動跑，檢查 data/derived/_meta.json 的 rebuilt_at 是否超過 180 小時沒更新，超過就發告警（需要 ALERT_WEBHOOK，沒設就只留在 Actions 紀錄裡）。 這支自己絕不能失敗——檢查不過只是 warning，不會讓 workflow 顯示紅字。

03 驗收測試清單

部署完，用這張清單勾過一次，確認「真的有通」而不是「檔案有放對地方」。

  • pytest -q 全過（對照基準：最新交接記錄 154 passed，數字變少要查為什麼）
  • 本機 streamlit run app/streamlit_app.py 打得開，8 個分頁（總經導航／短線／長波段／價值／定存／個股查詢／多軌體檢／主動式ETF）都能切換不噴 traceback
  • Streamlit Cloud 網址打得開，個股查詢頁不是顯示「拉不到 bundle」（代表 Secrets 有設對）
  • 三清單頁面的「資料日期／重算時間」不是很舊的日期，且沒有「清單過期」的紅字警告
  • 手動跑一次 rebuild.yml（Actions → 選 workflow → Run workflow）是綠的，data/derived/_meta.json 的 rebuilt_at 有更新
  • 手動跑一次 heartbeat.yml 確認 jq 解析邏輯沒壞（webhook 留空也能跑，只是不會真的發通知）
  • git status 乾淨：.env、positions*.json、data/upstream/、data/cache/、*.parquet 都沒有被意外加進版控
  • 三張清單 JSON（data/derived/{value,deposit,swing}_list.json）確實有進 git 歷史；factors_*.parquet 確實沒有

06 FAQ

為什麼「長波段候選池」不給建議買價、也不排名次？

因為它從沒被回測驗證過報酬或勝率——唯一測過的是「可行性普查」：中位數每週 2–5 檔候選、空頭週接近空手。這代表它篩得動、不代表跟著它買會賺。目前只給風控算出來的可買上限（停損 ÷ (1-10%)）與失效條件，不給 verdict。

價值／定存清單的回測數字準嗎？

2026-09-07 做過一次組合層回溯（實驗 B），當時價值線 N=10 報酬 +20.42%／回撤 -21.3%，輸大盤 0050 同期（+24.16%／-17.6%）；定存線也輸對照的 0056。但回溯用的腳本 research/backtest_rebalance.py import 的 twswing.value 之後已經整包搬進 tw-hold、tw-swing 端刪除了原始檔案，現在重跑這支腳本會直接因為 import 失敗而炸掉，數字目前無法重現，需要先做搬移修正才能重新驗證。

三清單一直沒更新怎麼辦？

先確認 rebuild.yml 是不是真的有觸發——目前刻意只支援手動（workflow_dispatch）或 tw-swing 端主動 dispatch，沒有排程 cron。如果指望它自動天天跑，需要先接好其中一種自動觸發。heartbeat.yml 每週一會檢查 _meta.json 超過 180 小時沒重算就告警（要設 ALERT_WEBHOOK 才會真的通知到人）。

App 是不是深色主題？跟股票分析工具常見的深色風格不一樣？

曾經是——2026-09-08 版本是深色，但 2026-09-11 使用者裁決改成固定淺色「北歐靜謐」主題（低飽和灰綠 accent、白卡片、淺灰底），且刻意不跟隨系統深色模式切換。這是 App 本身的設計決定；本說明書沿用同一組色票（--thc-* 系列變數）但另外處理了淺／深色模式，因為說明書本身沒有理由強迫讀者用淺色看。

改 requirements.txt 的版本號安全嗎？

不建議隨意放寬。檔頭註解記著教訓：Cloud 用 >= 曾經抓到跟本地測試不同的 plotly 版本，個股頁的 K 線圖直接 AttributeError。要改版本，先在本機把 pytest -q 跟 streamlit run 都過一遍再上。

PAT 什麼時候要換？

依最新交接記錄：tw-hold-bundle-read PAT 約 2026-12-07 到期，建議 11 月底前換新；TWHOLD_DISPATCH_PAT（tw-swing 端用來觸發 tw-hold rebuild 的那顆）約 2027-09-08 到期。到期前沒換會讓 fetch_bundle.py 直接拉不到資料。

positions.json 會不會不小心外洩到公開 repo？

tw-hold 是 public repo，.gitignore 已經排除 positions.json / positions.*.json / data/positions/（進場價、部位大小、投入金額）。檔案裡特別註記「一旦 commit 進公開歷史就洗不掉」——本機操作務必自己再檢查一次 git status，不要靠 git add -A 硬加。

「主動式 ETF」的旗標可以當成三大法人買賣超看嗎？

不行，頁面本身就標明「非官方三大法人／投信買賣超」。這是抓法定公開揭露的 PCF 資料自己差分算出來的「認養旗標」，設計上永遠不 gate 任何進出場，純粹是 context 標籤。

07 安全聲明

  • 不是投資建議——全站每頁都掛這句免責聲明；清單的 verdict／買價是規則算出來的，不是預測，不上真錢（tw-swing 才是真錢系統，tw-hold 純決策支援）。
  • tw-hold 是 public repo——App 頁面本身公開沒關係，但 .env、任何 PAT／API key、私有端點 URL 絕不能進版控；.gitignore 已排除 .env、*.token、*.pat、positions*.json。
  • PAT 建議用 fine-grained token、只給 contents: read 這一種最小權限，且限定在 tw-swing 單一 repo，不要核發成 classic token 或全 repo 權限。
  • 抓外部資料尊重來源站規範：投信 PCF 是法定公開揭露、TWSE STOCK_DAY_ALL 是官方公開行情，都只做低頻讀取，不轉發全量、不重製成別的產品。
  • 個股查詢刻意限制在 bundle 內約 1,000 檔，不做即時單股抓取——這是 PRD 明定的邊界，不是效能限制順便定的。
